# jev-idea

Jev（TypeSafe AI の判定専用モデル）を判定エンジンとして、開発の「手のリズムを止める
原因」を断つ 4 つのアイデアを設計・実装するリポジトリ。

解く問題は共通している。コードを書く時間そのものではなく、その周辺 —— 仕様漏れの
レビュー往復、文脈を探す時間、環境の再現、テストの重複記述 —— が開発のリズムを壊す。
4 つのアイデアはいずれも、これらを**判定に変換**して Jev に委ねる。

| # | アイデア | 何を Jev に委ねるか | 設計書 |
|---|---|---|---|
| 1 | 要件アサーション駆動開発 | 宣言と実装の整合、要件自体の妥当性 | [docs/01-requirement-assertions.md](docs/01-requirement-assertions.md) |
| 2 | 思考ログ（思考差分）の同期 | イベントの分類・集約、説明文の裏取り | [docs/02-thought-graph.md](docs/02-thought-graph.md) |
| 3 | インスタント・フォーク | 機密の有無、復元の再現性 | [docs/03-instant-fork.md](docs/03-instant-fork.md) |
| 4 | コードとテストの双対自動生成 | 反例の審判、テスト強度、収束判定 | [docs/04-dual-generation.md](docs/04-dual-generation.md) |

全体像と共通の設計原則は [docs/00-overview.md](docs/00-overview.md) に、共通判定
レイヤー jev-core の設計（judge() インターフェース、確率の確定規則、メタ分離
プロトコル）は [docs/05-jev-core.md](docs/05-jev-core.md) にまとめている。
設計の前提となる実測知見（Jev のレイテンシ・コスト・境界の不安定さ、確率回答を二値に
潰す場所が誤判定の入り口になること）は姉妹リポジトリ
[jev-claude](https://github.com/takezou621/jev-claude) で確定済みであり、本リポジトリは
それを継承する。

## 構成（予定）

```
jev-idea/
├── README.md
├── docs/            # 設計書（現状ここが本体）
└── packages/        # 実装フェーズで追加
    ├── core/        # 共通判定レイヤー（質問スキーマ・確率の扱い・ログ・回帰）
    ├── dual/        # アイデア 4: 双対自動生成ループ
    ├── thought-graph/  # アイデア 2: 思考グラフ収集・参照
    └── ...          # アイデア 1, 3 は設計書の実装計画に従う
```

実装の着手順は overview のロードマップを参照（結論: 4 → 2 → 1 → 3。判定ループが
本質でインフラ要らずの 4 から着手し、フック資産を再利用する 2、型システム設計が重い
1、OS レベル技術の検証が要る 3 の順）。
